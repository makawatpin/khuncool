# หมู่บ้านมาตราตัวสะกด — สื่อสอนก่อนเล่นเกม

## ภาพรวม

สร้างสื่อภาษาไทยเรื่องมาตราตัวสะกดสำหรับ ป.1–ป.3 ที่เส้นทางการเรียนชัดเจนว่า
**เรียนรู้ → ลองตอบระหว่างเรียน → เล่นเกมประยุกต์ → ดูผลและกลับไปทบทวน**

- ชื่อใช้งานชั่วคราว: **หมู่บ้านมาตราตัวสะกด**
- Route หน้ารวม: `/media/thai/final-consonants`
- Route หน้าเฉพาะมาตราในเฟสแรก: `/media/thai/mae-kot`
- กลุ่มหลัก: ครูฉายขึ้นจอและสอนทั้งห้อง
- กลุ่มรอง: นักเรียนเล่นทบทวนเองบนมือถือหรือแท็บเล็ต
- ระยะเวลา: บทเรียน 10–15 นาที + เกม 5–10 นาที
- การใช้งาน: ฟรี ไม่ต้องสมัคร ไม่ต้องติดตั้ง

สื่อนี้ไม่ใช่เกมคำถามที่มีบทอธิบายแทรกอยู่เล็กน้อย ส่วนสอนต้องใช้งานได้ด้วยตัวเอง
เหมือนสไลด์สอนแบบโต้ตอบ และเกมต้องใช้ความรู้ที่เพิ่งสอนโดยตรง

## สถาปัตยกรรมหน้า: path แยก แต่ใช้ระบบร่วม

หน้าเฉพาะมาตราใช้ path จริง ไม่ใช้ query string เป็น URL หลัก และไม่ส่งผู้ใช้ไปหน้า `/play`
เมื่อกดเริ่มเกม เกมจะเปิดต่อในหน้าเดิมทันที

```text
/media/thai/final-consonants   หน้ารวม บทนำ เลือกบท และเกมทบทวนหลายมาตรา
/media/thai/mae-kot            บทเรียนแม่กด + เกมเปรียบเทียบ กด/กก/กบ
```

เฟสแรกสร้างเพียงสองหน้านี้ให้สมบูรณ์ก่อน เมื่อบทเรียน เกม responsive และผลทดสอบผ่านแล้ว
จึงขยายหน้าอื่นจาก component และ data schema เดียวกัน ห้ามสร้างหน้าแม่ทั้ง 9 พร้อมกัน

หน้าในอนาคตอาจมี `/mae-kong`, `/mae-kom`, `/mae-koei`, `/mae-koew`, `/mae-kok`,
`/mae-kon`, `/mae-kop` และ `/mae-kaa` แต่แต่ละหน้าต้องมีเนื้อหาเฉพาะจริง ไม่ใช่เปลี่ยนเพียงชื่อแม่
ตัวอักษร และรายการคำ เพราะเสี่ยงเป็น thin/duplicate content และไม่มีคุณค่าพอสำหรับผู้เรียน

### Publication gate ป้องกัน thin/duplicate content

การมีข้อมูลมาตราอยู่ใน `familyData.ts` ไม่ได้แปลว่าหน้านั้นพร้อมเผยแพร่ หน้าเฉพาะมาตราต้องผ่าน
publication gate ก่อนจึงจะ index ได้

```ts
type FamilySeoContent = {
  status: "draft" | "ready";
  uniqueIntroduction: string;
  soundExplanation: string;
  consonantExplanation: string;
  commonErrors: Array<{ word: string; mistake: string; explanation: string }>;
  contrastLesson: { families: FamilyId[]; explanation: string };
  classroomActivity: string;
  teacherCheck: string;
  faqs: Array<{ question: string; answer: string }>;
  metaTitle: string;
  metaDescription: string;
};
```

หน้า `ready` ต้องมีครบทุกช่องและผ่านการตรวจโดยคน ส่วนหน้า `draft` ต้อง:

- ไม่ถูกใส่ใน sitemap หรือรายการลิงก์หน้า `/media/thai`
- ไม่ถูกลิงก์จากการ์ด “มาตราถัดไป”
- ถ้ามี route สำหรับ preview ต้องส่ง `robots: { index: false, follow: false }`
- ไม่ใช้ canonical ชี้ไปหน้ารวมเพื่อพยายามแก้เนื้อหาซ้ำ แต่เก็บเป็น draft จนมีคุณค่าพอจะมี canonical ของตัวเอง

หากภายหลังใช้ dynamic route ให้ `generateStaticParams()` สร้างเฉพาะรายการ `ready` และกำหนด
`dynamicParams = false` เพื่อให้ slug ที่ยังไม่พร้อมเป็น 404 แทนการสร้างหน้าบางอัตโนมัติ

การตรวจความพร้อมห้ามใช้จำนวนคำขั้นต่ำอย่างเดียว เพราะข้อความยาวแต่ซ้ำกันก็ยังเป็น thin content ได้
ต้องตรวจความเฉพาะของคำอธิบาย จุดสับสน ตัวอย่าง กิจกรรม และ FAQ ของมาตรานั้นจริง

## เป้าหมายการเรียนรู้

หลังเรียนและเล่นจบ นักเรียนควรทำได้ดังนี้

1. บอกได้ว่าตัวสะกดคือพยัญชนะท้ายพยางค์และทำให้เสียงท้ายของคำเปลี่ยนไป
2. แยกคำไม่มีตัวสะกดในแม่ ก กา ออกจากคำที่มีตัวสะกดได้
3. จำแนกคำในมาตราตรงมาตรา 4 แม่: กง กม เกย เกอว
4. จำแนกคำในมาตราไม่ตรงมาตรา 4 แม่: กก กด กน กบ โดยฟังเสียงท้าย ไม่เดาจากรูปตัวอักษรอย่างเดียว
5. อธิบายเหตุผลง่าย ๆ ได้ เช่น “เมฆอยู่แม่กก เพราะออกเสียงท้าย ก”

## หลักการออกแบบเนื้อหา

### หนึ่งคลังความรู้ สองการใช้งาน

บทเรียนและเกมอ่านข้อมูลจากแหล่งเดียวกัน (`families` และ `words`) เพื่อไม่ให้คำเฉลย
คำอธิบาย หรือการจัดมาตราคลาดกันระหว่างสองส่วน

- คำตัวอย่างหลักใช้ในบทเรียน
- คำฝึกใช้ในคำถามเช็กความเข้าใจ
- คำถ่ายโอนใช้ในเกม เป็นคำใหม่ที่ใช้กฎเดิม

เกมจึงไม่ควรวนถามเฉพาะคำที่เด็กเพิ่งเห็น เพราะจะวัดความจำมากกว่าความเข้าใจ

### เกมหน้าแม่เดียวต้องมีตัวลวงจากแม่ที่สับสน

หน้าเฉพาะมาตราไม่ได้แปลว่าเกมมีคำตอบจากมาตรานั้นอย่างเดียว ค่า `focusFamily` กำหนดหัวข้อที่
บทเรียนและผลลัพธ์เน้น แต่ตัวสร้างคำถามต้องผสมมาตราที่มีเสียงท้ายใกล้กันเสมอ

| หัวข้อที่เน้น | ชุดเปรียบเทียบในเกม | เหตุผล |
|---|---|---|
| แม่กด / แม่กก / แม่กบ | กด–กก–กบ | เสียงท้ายแบบกัก ต้องแยกตำแหน่งและเสียงปลายคำ |
| แม่กน / แม่กง / แม่กม | กน–กง–กม | เสียงนาสิกใกล้กัน |
| แม่เกย / แม่เกอว / แม่ ก กา | เกย–เกอว–ก กา | แยกเสียง ย ว และคำไม่มีตัวสะกด |

รอบมาตรฐาน 10 ข้อของหน้าแม่กดใช้สัดส่วน กด 4 ข้อ กก 3 ข้อ กบ 3 ข้อ แล้วสลับลำดับ
ผู้เล่นจึงเดาแม่กดทุกข้อแล้วได้ไม่เกิน 40% ขณะเดียวกันผลลัพธ์ยังมีข้อมูลแม่กดมากพอสำหรับ
ชี้จุดที่ต้องทบทวน ห้ามสร้างโจทย์โดยตั้งชื่อแม่เป้าหมายเป็นคำตอบที่ถูกเกือบทุกข้อ

### สอนเสียงก่อนรายชื่อพยัญชนะ

ตอนสอนมาตราไม่ตรงมาตรา ให้เริ่มจากการฟังเสียงท้าย เช่น `/ก/`, `/ด/`, `/น/`, `/บ/`
แล้วค่อยเปิดให้เห็นว่ามีพยัญชนะหลายตัวที่ออกเสียงท้ายเดียวกัน วิธีนี้ลดการท่องรายชื่อ
โดยไม่เข้าใจหลัก

### คำต้องตรวจได้และไม่กำกวม

- เลือกคำพยางค์เดียวหรือคำที่ระบุพยางค์เป้าหมายชัดเจนก่อน
- เก็บ `initial`, `vowel`, `final`, `familyId`, `endingSound` แยกกัน ไม่วิเคราะห์คำจาก string ตอนรัน
- หลีกเลี่ยงคำยืม คำควบกล้ำซับซ้อน การันต์ และคำที่มีข้อถกเถียงในเวอร์ชันแรก
- คลังคำและเสียงอ่านต้องผ่านการตรวจโดยครูภาษาไทยก่อนเผยแพร่
- เสียงอ่านใช้ไฟล์ที่เตรียมไว้ ไม่พึ่ง Speech Synthesis ของเครื่องผู้ใช้

## ขอบเขตเนื้อหา

เวอร์ชันแรกครอบคลุม 9 มาตรา โดยจัดเป็น 3 กลุ่ม

| กลุ่ม | มาตรา | หลักที่สอน |
|---|---|---|
| ไม่มีตัวสะกด | แม่ ก กา | พยางค์จบด้วยเสียงสระ ไม่มีพยัญชนะท้าย |
| ตรงมาตรา | กง กม เกย เกอว | ตัวสะกดตรงกับชื่อแม่: ง ม ย ว |
| ไม่ตรงมาตรา | กก กด กน กบ | ตัวเขียนต่างกันได้ แต่รวมแม่ตามเสียงท้าย |

จำนวนคำเป้าหมายสำหรับเปิดตัว:

- อย่างน้อย 8 คำต่อมาตรา รวมอย่างน้อย 72 คำ
- 3 คำตัวอย่างสอน + 2 คำฝึก + อย่างน้อย 3 คำใหม่สำหรับเกมต่อมาตรา
- ทุกคำมีคำอ่าน เสียงอ่าน การแยกส่วนคำ ระดับความยาก และคำอธิบายเฉลย

## เส้นทางผู้ใช้และหน้าจอ

### 1. หน้าเริ่มต้น

แสดงชื่อสื่อ เป้าหมาย และเส้นทางสองปุ่ม

- ปุ่มหลัก: `เริ่มเรียนทีละตอน`
- ปุ่มรอง: `เคยเรียนแล้ว ไปเล่นเกม`
- แสดงความคืบหน้าล่าสุดจาก localStorage แต่ไม่บังคับล็อกเกม

เหตุผลที่ไม่ล็อกเกม: ครูอาจสอนเนื้อหามาก่อนแล้วและต้องการเปิดเกมทันที แต่ลำดับภาพและ
ข้อความต้องชี้นำให้ผู้ใช้ใหม่เริ่มที่บทเรียน

**ตัวบีบ:** จอเตี้ย เพราะหัวเรื่อง คำอธิบาย สถานะ และสองปุ่มเรียงในแนวตั้ง

### 2. แผนที่บทเรียน

มี 4 ตอน เรียงตามลำดับแนวคิด

1. ตัวสะกดอยู่ตรงไหน
2. แม่ ก กา และมาตราตรงมาตรา
3. มาตราไม่ตรงมาตรา
4. สรุปแผนที่ 9 มาตรา

แต่ละการ์ดบอกเวลาประมาณ 2–4 นาทีและสถานะ เรียนแล้ว/ยังไม่เรียน

**ตัวบีบ:** จอตั้งขาดความกว้าง การ์ด 4 ใบต้องเป็น 2×2 หรือแถวเดียวที่อ่านครบโดยไม่ซ่อนปุ่ม

### 3. บทเรียนที่ 1 — ตัวสะกดอยู่ตรงไหน

ใช้คำหนึ่งคำแยกเป็นชิ้นส่วนแบบเคลื่อนไหวอย่างมีขั้นตอน เช่น

`จ + า + น → จาน`

- ขั้น 1 เห็นคำเต็มและฟังเสียง
- ขั้น 2 เน้นพยัญชนะต้นและสระ
- ขั้น 3 เน้นตัวสะกด พร้อมฟังเสียงท้าย
- เปรียบเทียบคำคู่ เช่น `จา / จาน` เพื่อให้เห็นว่าตัวสะกดเปลี่ยนเสียงอย่างไร
- ครูควบคุมด้วย ก่อนหน้า/ถัดไป/เล่นเสียง/เล่นอัตโนมัติ

จบตอนด้วยคำถามไม่คิดคะแนน 2 ข้อ หากผิดให้อธิบายแล้วลองใหม่

**ตัวบีบ:** จอเตี้ย เพราะการแยกส่วนคำ + คำอธิบาย + แถบควบคุมกินความสูงพร้อมกัน

### 4. บทเรียนที่ 2 — แม่ ก กา และมาตราตรงมาตรา

สอนทีละบ้าน ไม่แสดงข้อมูลทั้งห้าบ้านพร้อมกันในตอนแรก

- แม่ ก กา: ไม่มีตัวสะกด
- แม่กง: ลงท้ายเสียง ง
- แม่กม: ลงท้ายเสียง ม
- แม่เกย: ลงท้ายเสียง ย
- แม่เกอว: ลงท้ายเสียง ว

แต่ละบ้านมีชื่อแม่ สัญลักษณ์เสียง ตัวอย่าง 3 คำ ปุ่มฟัง และภาพแยกตัวสะกด
จากนั้นมีหน้าสรุป 5 บ้านและคำถามเช็กความเข้าใจ 3 ข้อ

**ตัวบีบ:** หน้าสรุปบนจอตั้งขาดความกว้าง ห้ามย่อบ้านจนตัวหนังสือต่ำกว่าเกณฑ์

### 5. บทเรียนที่ 3 — มาตราไม่ตรงมาตรา

สอนจากเสียงท้ายก่อน แล้วค่อยเปิดรายชื่อพยัญชนะที่อยู่ในแม่เดียวกัน

- แม่กก: เสียงท้าย ก
- แม่กด: เสียงท้าย ด
- แม่กน: เสียงท้าย น
- แม่กบ: เสียงท้าย บ

หนึ่งตัวอย่างควรมีลำดับ `ฟังคำ → เดาเสียงท้าย → เปิดตัวสะกด → เปิดชื่อแม่ → อธิบาย`
คำอธิบายต้องย้ำว่าให้ฟังเสียงท้าย ไม่ใช่เลือกแม่จากหน้าตาของตัวอักษร

จบตอนด้วยคำถามเช็กความเข้าใจ 4 ข้อ โดยอย่างน้อย 2 ข้อใช้ตัวสะกดไม่ตรงชื่อแม่

**ตัวบีบ:** จอเตี้ยจากลำดับเปิดเผยหลายชั้น และข้อความอธิบายอาจยาวที่สุดในทั้งสื่อ

### 6. บทเรียนที่ 4 — สรุปแผนที่ 9 มาตรา

แสดงบ้าน 9 หลังเป็นตาราง 3×3 พร้อมชื่อแม่ เสียงท้าย และตัวอย่างสั้นหนึ่งคำ

- กดบ้านเพื่อเปิดรายละเอียดและฟังตัวอย่าง
- มีตัวกรอง `ไม่มีตัวสะกด / ตรงมาตรา / ไม่ตรงมาตรา`
- ปุ่มหลักท้ายหน้า: `พร้อมแล้ว ไปส่งคำกลับบ้าน`

**ตัวบีบ:** จอตั้งขาดความกว้าง และจอเตี้ยขาดความสูง ตารางต้องยุบได้โดยไม่กลายเป็นพื้นที่ scroll ที่ซ่อนบ้าน

### 7. ตั้งค่าเกม

ครูเลือกได้เฉพาะตัวเลือกที่มีผลต่อการสอนจริง

- ขอบเขต: ตรงมาตรา / ไม่ตรงมาตรา / ครบ 9 มาตรา
- จำนวนข้อ: 5 / 10 / 15
- ระดับ:
  - เริ่มต้น: เน้นตัวสะกด + 3 ตัวเลือก + เปิดเสียงได้
  - ฝึกคล่อง: ไม่เน้นตัวสะกด + 4 ตัวเลือก
  - ท้าทาย: ฟังคำก่อน แล้วเปิดคำเมื่อขอคำใบ้
- เล่นทั้งห้องหรือทีม 2–4 ทีม
- เปิด/ปิดเสียงและคำใบ้

ค่าเริ่มต้นคือ `ตรงมาตรา · 10 ข้อ · เริ่มต้น · ทั้งห้อง` เพื่อไม่ให้เด็กเจอโจทย์ยากเกินไป

**ตัวบีบ:** จอเตี้ย เพราะกลุ่มตัวเลือกหลายแถว ต้องจัดแบบสองคอลัมน์เมื่อกว้างและลดคำอธิบายเมื่อ short

### 8. เกม — ส่งคำกลับบ้าน

หนึ่งรอบแสดงคำเพียงคำเดียว เพื่อลดภาระการอ่านบนโปรเจกเตอร์

1. เลือกชุดเปรียบเทียบตาม `focusFamily` เช่น หน้าแม่กดใช้ กด–กก–กบ
2. แสดงภาพ/เล่นเสียง/แสดงคำตามระดับ
3. นักเรียนฟังเสียงท้ายและปรึกษากัน
4. ครูกดบ้านจากตัวเลือก 3–4 หลัง ไม่ใช้ drag เป็นวิธีหลัก
5. ถ้าถูก บ้านสว่างและได้คะแนน
6. ถ้าผิด ไม่ข้ามทันที แต่เปิดตัวสะกด เสียงท้าย และเหตุผลสั้น ๆ แล้วให้ลองอีกครั้ง
7. ไปคำถัดไปและสลับทีมอัตโนมัติ

การกดเลือกแทนการลากทำให้ใช้ได้ทั้งเมาส์ จอสัมผัส และคีย์บอร์ด และช่วยให้ audit ตรวจว่า
ปุ่มถูกบังหรือกดไม่ได้ได้ตรงกว่า

**ตัวบีบ:**

- จอเตี้ย: toolbar + คะแนนทีม + คำ + บ้านตัวเลือก + feedback อยู่พร้อมกัน
- จอตั้ง: บ้าน 4 ตัวเลือกต้องเป็น 2×2 และข้อความยาวสุดต้องไม่ดันปุ่มตก

### 9. ผลลัพธ์และทบทวน

แสดงผลที่นำไปสอนได้ ไม่ใช่เพียงคะแนนรวม

- ถูกครั้งแรกกี่ข้อ
- ลองใหม่แล้วถูกกี่ข้อ
- ผิดบ่อยในแม่ใด
- รายการคำที่ควรทบทวน พร้อมปุ่มฟังและเหตุผล
- ปุ่ม `ทบทวนบทที่เกี่ยวข้อง`, `เล่นเฉพาะคำที่ผิด`, `เล่นอีกครั้ง`

การนับ “ถูกครั้งแรก” แยกจาก “แก้จนถูก” เพื่อให้ผลไม่หลอกว่าผู้เรียนเข้าใจตั้งแต่แรก

**ตัวบีบ:** รายการคำผิดยาวบนทุกทรง อนุญาตให้รายการผลลัพธ์ scroll ได้ แต่ปุ่มการกระทำหลักต้องไม่ซ่อนหลัง scroll

## Responsive และ accessibility contract

ต้องทำตาม `docs/how-to-brief.md` และ `docs/media-stage-contract.md` ดังนี้

- ใช้ `useStage()` กับโครง `.kc-stage` → `.kc-stage-body` สองชั้น
- ตัวเกมห้ามอ่าน viewport และห้ามใช้ `vw`, `vh`, `dvh`, `innerWidth`, `matchMedia`
- geometry ทุกค่าอยู่ใน CSS Module; inline styleใช้เฉพาะสีหรือ state value ที่จำเป็น
- ใช้ token wide / portrait / short และ `cqi` / `cqb`
- toolbar ใช้ `.kc-tap-chrome`; ปุ่มเกมใช้ `.kc-tap`
- ของตกแต่งทุกชิ้นใช้ `pointer-events: none`
- โจทย์ คำเฉลย feedback และคำถัดไปอยู่ใน `role="status" aria-live="polite"`
- ทุกกิจกรรมเล่นได้ด้วยการกดและคีย์บอร์ด ไม่บังคับ drag
- เคารพ `prefers-reduced-motion`; animation ไม่เป็นช่องทางเดียวในการบอกถูก/ผิด
- ข้อความไม่ต่ำกว่า 11px เป้าแตะไม่ต่ำกว่า 24×24px และปุ่มหลักควรถึง token ความสบายมือ
- ที่ 844×390 ต้องมี headroom อย่างน้อย 60px ก่อน hard fail
- ห้ามใช้ `overflow:auto` เพื่อซ่อนปุ่มเริ่ม ปุ่มถัดไป บ้านคำตอบ หรือปุ่มสรุป

## ลำดับการพัฒนา

### ระยะ 1 — ล็อกเนื้อหา

- ทำรายการ 9 มาตราและคำอย่างน้อย 72 คำ
- เขียนคำอธิบายและ common mistake
- ตรวจการจัดมาตราและคำอ่านกับครูภาษาไทย
- เตรียมเสียงอ่านและตรวจไฟล์กับข้อมูล

### ระยะ 1.5 — พิสูจน์เทมเพลตด้วยแม่กด

- ทำเนื้อหาเฉพาะแม่กด คำที่สับสน และคำเปรียบเทียบแม่กก/แม่กบให้เสร็จ
- ตรวจว่าหน้าเดียวรองรับสอน เช็กความเข้าใจ และเล่นเกมต่อเนื่องโดยไม่เปลี่ยน route
- ตรวจว่าสัดส่วนโจทย์ 4:3:3 วัดการจำแนกจริงและไม่บอกคำตอบจากบริบท
- ยังไม่สร้างหน้าแม่อื่นจนกว่าแม่กดจะผ่านการตรวจเนื้อหา ภาพจริง และ audit

### ระยะ 2 — สร้างแกนบทเรียน

- ทำหน้าเริ่ม แผนที่บทเรียน และบทเรียน 4 ตอน
- ทำ WordBreakdown และ FamilyHouse ให้ใช้ซ้ำได้
- ทำ lesson check แบบลองใหม่ได้และไม่คิดคะแนน
- บันทึกความคืบหน้าในเครื่อง

### ระยะ 3 — สร้างเกมจากข้อมูลเดียวกัน

- ทำหน้าตั้งค่า ตัวสร้างคำถาม เกม feedback และผลลัพธ์
- เพิ่มทีม 2–4 ทีมโดยเก็บคะแนนในเกมเท่านั้น
- เพิ่มเล่นเฉพาะคำที่ผิดและลิงก์กลับบทเรียนที่เกี่ยวข้อง

### ระยะ 4 — เชื่อมหน้าเว็บและ SEO

- เพิ่ม resource ใน `app/media/subjectContent.ts`
- เพิ่ม route ใน sitemap ผ่าน catalog เดิม
- ทำ metadata, BreadcrumbList, LearningResource, WebApplication และ FAQ
- เชื่อมจากหน้า `/media/thai` และจากสื่อ `thai-kingdom`
- กำหนด canonical ของหน้าแม่กดเป็น `/media/thai/mae-kot` โดยตรง ไม่มี canonical ไปหน้า query หรือหน้า play
- หลังพิสูจน์แม่กดแล้ว แต่ละหน้าที่ขยายต้องผ่านเกณฑ์เนื้อหาเฉพาะก่อนเพิ่มเข้า sitemap
- เพิ่ม automated content gate ให้ build/test ล้มเหลวหากหน้า `ready` ขาดส่วนบังคับ หรือ metadata ซ้ำกับหน้าอื่น
- ตรวจว่าหน้า `draft` ไม่ปรากฏใน sitemap, subject navigation และ internal recommendation

### ระยะ 5 — ตรวจคุณภาพ

- เพิ่มและพิสูจน์ audit config
- ตรวจ 7 ขนาดที่ audit ใช้ × ในหน้า/เต็มจอ × ทุกหน้าจอ
- ตรวจ headroom และ accessibility
- เปิด screenshot ตรวจความสมดุลด้วยตาแล้วแก้ก่อนรัน audit รอบสุดท้าย

## เกณฑ์ตรวจรับ

- ผู้ใช้ใหม่เรียนตามลำดับ 4 ตอนแล้วเข้าเกมได้โดยไม่ต้องอ่านคำอธิบายนอกเวที
- หน้าแม่กดสอนและเปิดเกมต่อใน route เดิมโดยไม่มี hop ไปหน้า play
- เกมหน้าแม่กดมีคำจากแม่กด แม่กก และแม่กบตามสัดส่วนที่กำหนด
- การเดาแม่กดทุกข้อทำคะแนนรอบมาตรฐานได้ไม่เกิน 40%
- หน้าเฉพาะมาตราที่ index ได้ต้องมี `status: "ready"` และผ่าน publication gate
- หน้า `draft` ต้องไม่อยู่ใน sitemap/internal navigation และต้องไม่ถูก index
- `metaTitle` และ `metaDescription` ของหน้า ready ต้องไม่ซ้ำกัน
- ทุกคำในเกมมีเฉลยชื่อแม่ เสียงท้าย และเหตุผลที่อ้างจากข้อมูลเดียวกับบทเรียน
- เกมมีคำใหม่ที่ไม่ปรากฏในตัวอย่างสอน แต่ใช้กฎที่สอนไปแล้ว
- ตอบผิดแล้วได้เรียนรู้และลองใหม่ ไม่ถูกข้ามด้วย animation อย่างเดียว
- ผลลัพธ์ชี้ได้ว่าควรกลับไปทบทวนมาตราใด
- ไม่มีการจัดมาตราแบบวิเคราะห์จากตัวอักษรอัตโนมัติที่อาจผิดกับคำพิเศษ
- hard fails, unreachable, undersizedTargets และ smallText เท่ากับ 0
- ไม่มีปุ่มคำตอบหรือปุ่มนำทางถูกซ่อนหลัง scroll
- 844×390 เหลือ headroom อย่างน้อย 60px
- screenshot ทุกหน้าจอผ่านการตรวจด้วยตาทั้งในหน้าและเต็มจอ
