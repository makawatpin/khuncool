# กระดานป้ายปริศนา (/mystery-board) — Design

วันที่: 2026-08-27
สถานะ: อนุมัติดีไซน์แล้ว รอเขียนแผน implement

## 1. เป้าหมาย

เครื่องมือหน้าชั้นเรียนสำหรับ "สุ่มเปิดป้าย" — นักเรียนเลือกป้ายบนกระดาน
ป้ายพลิกเผยสิ่งที่ซ่อนอยู่ (คะแนน/การ์ดพิเศษ หรือคำถามของครู) ใช้ฉายขึ้น
โปรเจกเตอร์เพื่อกระตุ้นการมีส่วนร่วมท้ายคาบหรือระหว่างทบทวนบทเรียน

จุดขายคือ **แอนิเมชันจัดเต็ม** — ป้ายพลิก 3D, ไฟวิ่งไล่ตอนสุ่ม, คอนเฟตตี,
จอสั่นตอนโดนกับดัก พร้อมเสียงประกอบ

### ไม่อยู่ในขอบเขต (YAGNI)

- ไม่มีระบบทีม/คะแนนสะสม — ครูจดเองหรือใช้ `/group-scoreboard` คู่กัน
- ไม่มีการบันทึกลง Supabase (ยกเว้น usage event ผ่าน `trackToolEvent`)
- ไม่มีการสุ่มชื่อนักเรียน — ใช้ `/random-name-picker` คู่กันได้
- ไม่มีการแชร์กระดานข้ามเครื่อง

## 2. โครงไฟล์

ตามแบบเดียวกับ `/group-scoreboard` และ `/duck-race`:

| ไฟล์ | หน้าที่ |
|---|---|
| `app/mystery-board/page.tsx` | Server component: metadata, JSON-LD (WebApplication + HowTo + FAQPage), breadcrumb, header, howto/use-case/FAQ sections |
| `app/mystery-board/MysteryBoardApp.tsx` | `"use client"` — ตัวเกมทั้งหมด (state, เสียง, คอนเฟตตี) |
| `app/mystery-board/MysteryBoardApp.module.css` | keyframes + คลาสแอนิเมชันทั้งหมด ตามแบบเกมใน `app/media/**` |

**หมายเหตุแยกไฟล์:** ตัวเกมมีสาม state ใหญ่ (setup / board / reveal) ถ้า
`MysteryBoardApp.tsx` เกิน ~600 บรรทัด ให้แยก `SetupPanel.tsx` และ
`RevealOverlay.tsx` ออกมาเป็น component ลูกในโฟลเดอร์เดียวกัน โดย
`MysteryBoardApp.tsx` ยังถือ state ทั้งหมดและส่งลงไปเป็น props

**การลงทะเบียนเครื่องมือ:**

- เพิ่ม entry ใน `TOOLS` ของ `app/tools/data.ts`
  (`icon: "🎁"`, `href: "/mystery-board"`, `bg: "#FFEAD5"`,
  `image: "/assets/tool-covers/mystery-board.webp"`)
- เพิ่ม 1 entry ใน `CASES` — คำถาม "อยากให้ท้ายคาบสนุกขึ้น ไม่ให้เด็กเบื่อ"
- ไม่ต้องแก้ `app/sitemap.ts` — sitemap สร้าง route จาก `TOOLS` ให้เองอยู่แล้ว
- ต้องมีไฟล์ cover `public/assets/tool-covers/mystery-board.webp` พร้อมกับ
  entry ใน `TOOLS` เพราะการ์ดบนหน้า `/tools` ใช้รูปนี้

## 3. โมเดลข้อมูล

```ts
type Mode = "score" | "question";
type Theme = "space" | "treasure" | "neon";

type PrizeKind = "points" | "double" | "steal" | "bomb" | "lucky";

type Tile = {
  id: number;          // 1..size, ใช้เป็นเลขหน้าป้าย
  opened: boolean;
  // โหมดคะแนน
  prize?: { kind: PrizeKind; value: number; label: string; emoji: string };
  // โหมดคำถาม
  question?: string;
};

type Settings = {
  mode: Mode;
  size: 12 | 20 | 30;    // ขนาดที่ครูเลือก
  theme: Theme;
  soundOn: boolean;
  questions: string[];   // ใช้เฉพาะโหมดคำถาม
};
```

`Settings.size` คือขนาดที่ครูเลือกไว้ ส่วนจำนวนป้ายจริงของกระดานคือ
`tiles.length` ซึ่งอาจน้อยกว่าเมื่อโหมดคำถามมีคำถามไม่พอ (ดูข้อ 4)
ตัวนับบนกระดานและการสุ่มต้องอ้าง `tiles.length` เสมอ ไม่ใช่ `settings.size`

**Persistence:** `localStorage` คีย์ `khuncool.mysteryboard` เก็บ `Settings`
เท่านั้น (โหมด/ขนาด/ธีม/เสียง/ชุดคำถาม) — สถานะป้ายที่เปิดแล้วอยู่ใน React
state ล้วน ปิดหน้าเว็บแล้วเริ่มใหม่เสมอ เพราะเกมจบในคาบเดียว

โหลด/บันทึกตามแพตเทิร์นของ `ScoreboardApp.tsx`: มี `hydrated` flag กัน
hydration mismatch และ `try/catch` รอบ `JSON.parse`

## 4. เนื้อหาหลังป้าย

### โหมดคะแนน (ไม่ต้องเตรียมอะไร)

ระบบสุ่มแจกให้ครบทุกป้ายตอนเริ่มเกม โดยยึดสัดส่วนคงที่แล้ว shuffle:

| ชนิด | สัดส่วนโดยประมาณ | หน้าตา |
|---|---|---|
| `points` แต้มธรรมดา (+5 / +10 / +20) | ~55% | 🎉 "ได้ 10 คะแนน" |
| `points` แจ็กพอต (+50) | ~8% | 💎 "แจ็กพอต! 50 คะแนน" |
| `double` คูณสอง | ~10% | ✨ "คะแนนรอบนี้ ×2" |
| `steal` ขโมยคะแนน | ~10% | 🦝 "ขโมย 10 คะแนนจากทีมอื่น" |
| `bomb` ระเบิด | ~12% | 💣 "เสีย 15 คะแนน" |
| `lucky` การ์ดโชคดี | ~5% | 🍀 "เลือกเปิดป้ายเพิ่มอีก 1 ใบ" |

การ์ดพิเศษเป็น **ข้อความบอกกติกา** เฉย ๆ ระบบไม่คิดคะแนนให้ (ไม่มีระบบทีม)
ครูเป็นคนตัดสินใจว่าจะให้ใครและบันทึกที่ไหน

ต้องการอย่างน้อย 1 แจ็กพอตและ 1 ระเบิดในทุกกระดาน (บังคับหลัง shuffle)

### โหมดคำถาม

ครูพิมพ์คำถามในกล่องข้อความ 1 บรรทัด = 1 คำถาม แล้วกด "เริ่มเกม"

- ถ้าคำถามน้อยกว่าจำนวนป้าย → ลดจำนวนป้ายลงให้เท่าจำนวนคำถามอัตโนมัติ
  พร้อมข้อความบอกครู (ป้ายเปล่าไม่มีประโยชน์)
- ถ้าคำถามมากกว่าจำนวนป้าย → สุ่มหยิบมาเท่าจำนวนป้าย
- ชุดคำถามบันทึกลง localStorage ใช้ซ้ำคาบหน้าได้ทันที
- ปุ่ม "ล้างคำถาม" สำหรับเริ่มชุดใหม่

## 5. หน้าจอและ flow

```
setup ──"เริ่มเกม"──> board ──เลือกป้าย/กดสุ่ม──> reveal ──"กลับกระดาน"──> board
  ^                     |                                                  |
  └──"ตั้งค่า"──────────┘                                                  |
                        └──เปิดครบทุกป้าย──> board (โชว์ปุ่ม "เริ่มใหม่")<─┘
```

### 5.1 หน้าตั้งค่า (setup)

- เลือกโหมด: การ์ด 2 ใบ (คะแนน / คำถาม)
- เลือกขนาดกระดาน: ปุ่ม 12 / 20 / 30 ป้าย
- เลือกธีม: space (อวกาศ) / treasure (สมบัติ) / neon (นีออน)
- ช่องพิมพ์คำถาม (แสดงเฉพาะโหมดคำถาม) + ตัวนับ "12 คำถาม"
- ปุ่ม "เริ่มเกม" — disabled ถ้าโหมดคำถามและยังไม่มีคำถามเลย

### 5.2 กระดาน (board)

- กริดป้าย responsive: มือถือ 3 คอลัมน์, แท็บเล็ต 4, จอใหญ่ 5–6
  (`grid-template-columns: repeat(auto-fit, minmax(...))`)
- ป้ายแต่ละใบ: เลขใหญ่กลางป้าย + ลวดลายตามธีม
- แถบบน: ชื่อเกม, ตัวนับ "เปิดแล้ว 7/20", ปุ่มปิดเสียง, ปุ่มเต็มจอ,
  ปุ่มตั้งค่า, ปุ่มเริ่มใหม่
- ปุ่มลอยด้านล่าง: "🎲 สุ่มป้าย" — disabled ระหว่างแอนิเมชันและตอนเปิดครบ
- ป้ายที่เปิดแล้ว: จางลงเป็นสีเทาแบน โชว์ผลลัพธ์ย่อ กดดูซ้ำได้แต่ไม่มี
  แอนิเมชัน (เปิด overlay แบบ fade ธรรมดา) กด "สุ่มป้าย" จะไม่เลือกป้ายนี้อีก
- เปิดครบทุกป้าย: โชว์แบนเนอร์ "เปิดครบแล้ว!" + คอนเฟตตี + ปุ่มเริ่มใหม่

### 5.3 หน้าเผยผล (reveal overlay)

1. ป้ายที่เลือก zoom ขึ้นกลางจอ ฉากหลังเบลอมืด (`backdrop-filter`)
2. ป้ายพลิก `rotateY(180deg)` 0.6 วิ
3. เนื้อหาโผล่:
   - โหมดคะแนน — emoji ใหญ่ + ตัวเลข/ข้อความรางวัล
   - โหมดคำถาม — ข้อความคำถามตัวใหญ่เต็มความกว้าง อ่านจากหลังห้องได้
4. ปุ่ม "กลับกระดาน" (และปุ่ม Esc / คลิกนอกป้ายก็ปิดได้)

## 6. แอนิเมชันและเสียง

ทั้งหมดทำด้วย CSS + Web Animations API + Web Audio — **ไม่เพิ่ม dependency**
(โปรเจกต์ไม่มีไลบรารีแอนิเมชันอยู่แล้ว)

| จังหวะ | เอฟเฟกต์ | เทคนิค |
|---|---|---|
| เข้ากระดาน | ป้ายไล่ขึ้นทีละใบ | `animation-delay: calc(var(--i) * 40ms)` |
| พื้นหลัง | gradient/ดาวเคลื่อนช้า | keyframes ใน module.css ตามธีม |
| hover / focus | ยกลอย + เงาเรือง + แสงกวาด | `transform`, `box-shadow`, `::after` sweep |
| กดสุ่ม | ไฟวิ่งไล่ทั่วกระดานเร็ว→ช้า ~2 วิ | `setTimeout` ไล่ index พร้อม easing แบบ decelerate แล้วหยุดที่เป้าหมาย |
| เลือกป้าย | ป้ายลอยขึ้นกลางจอ ฉากหลังเบลอ | overlay + `scale`/`translate` |
| พลิก | `rotateY` 3D 0.6 วิ + แสงวาบขอบ | `transform-style: preserve-3d`, `backface-visibility` |
| แจ็กพอต | คอนเฟตตี + วงแหวนแสง + ตัวเลขเด้ง | สร้าง `div` แล้ว `element.animate()` แบบเดียวกับ `burst()` ใน `DuckRaceApp.tsx` |
| ระเบิด | จอสั่น + แดงวูบ + ป้ายแตกร้าว | keyframes shake + overlay สีแดง |
| เสียง | click / whoosh / flip / jackpot / bomb | Web Audio สังเคราะห์เอง (oscillator + noise buffer) ตามแบบ `beep()` ใน `DuckRaceApp.tsx` — ไม่โหลดไฟล์เสียง |

**การสุ่มต้องสุ่มก่อน แอนิเมชันตามทีหลัง:** เลือกป้ายเป้าหมายด้วย
`Math.random()` จากป้ายที่ยังไม่เปิด แล้วค่อยเล่นไฟวิ่งให้ไปจบที่ป้ายนั้น
ไม่ใช่ปล่อยให้แอนิเมชันเป็นตัวตัดสิน

**Accessibility:**

- `@media (prefers-reduced-motion: reduce)` — ตัดการสั่น คอนเฟตตี และไฟวิ่ง
  เหลือ fade สั้น ๆ (แพตเทิร์นเดียวกับเกมใน `app/media/**`)
- ป้ายเป็น `<button>` จริง มี `aria-label` ("ป้ายหมายเลข 7, ยังไม่เปิด")
- overlay ปิดด้วย Esc, โฟกัสวิ่งเข้า overlay ตอนเปิดและกลับที่ป้ายเดิมตอนปิด
- เสียงปิดได้ และ `AudioContext` สร้างตอนผู้ใช้กดครั้งแรกเท่านั้น

**Cleanup:** ทุก `setTimeout` เก็บไว้ใน `Set` แล้วเคลียร์ตอน unmount และปิด
`AudioContext` ตอน unmount — ตามแพตเทิร์น `pendingTimeoutsRef` ใน
`DuckRaceApp.tsx` (ไฟวิ่งไล่ใช้ timeout หลายสิบตัว ถ้าไม่เคลียร์จะยิงหลัง
unmount)

## 8. SEO / เนื้อหาหน้า

`page.tsx` ทำตามโครงของ `app/group-scoreboard/page.tsx`:

- `metadata`: title "กระดานป้ายปริศนา สุ่มเปิดป้ายตอบคำถาม ใช้ฟรี | khuncool",
  description, keywords, `alternates.canonical`, openGraph (`locale: "th_TH"`),
  twitter card
- JSON-LD `@graph`: WebApplication + HowTo (4 ขั้น) + FAQPage (5 ข้อ)
- Breadcrumb: หน้าแรก › เครื่องมือครู › กระดานป้ายปริศนา
- Header: `<h1>` + คำโปรยแบบสั้น (มือถือ) / ยาว (จอใหญ่)
- ท้ายหน้า: วิธีใช้งาน, ใช้ทำอะไรได้บ้าง, คำถามที่ครูถามบ่อย,
  ลิงก์ไป `/group-scoreboard`, `/random-name-picker`, `/random-question`

## 9. การทดสอบ

โปรเจกต์ไม่มี test runner (มีแต่ `playwright` เป็น devDependency สำหรับ
สคริปต์ถ่ายภาพหน้าจอใน `scripts/`) การตรวจงานจึงเป็นแบบ manual + build:

1. `npm run lint` และ `npm run build` ผ่าน
2. ตรวจด้วยเบราว์เซอร์: setup → board → reveal → เปิดครบ → เริ่มใหม่
3. โหมดคำถาม: คำถามน้อยกว่าป้าย / มากกว่าป้าย / ไม่มีคำถาม
4. รีเฟรชหน้า — โหมด ขนาด ธีม และชุดคำถามต้องคงอยู่ ป้ายต้องรีเซ็ต
5. ทดสอบเต็มจอบนมือถือ (fallback) และเดสก์ท็อป (native)
6. เปิด `prefers-reduced-motion` แล้วยืนยันว่าไม่มีการสั่น/คอนเฟตตี
7. ตรวจ console ไม่มี warning เรื่อง state update หลัง unmount

## 10. ความเสี่ยง

- **จำนวน timeout ของไฟวิ่ง** — ถ้าครูกดสุ่มรัวหลายครั้ง ต้องกันด้วย
  `isAnimating` flag และยกเลิก timeout ชุดเก่าก่อนเริ่มชุดใหม่
- **กระดาน 30 ป้ายบนมือถือ** — ป้ายจะเล็กมาก แก้ด้วยกริดเลื่อนแนวตั้งและ
  ขนาดป้ายขั้นต่ำ ไม่บีบให้พอดีจอ
- **ขนาดไฟล์ CSS module** — เกมใน `app/media/**` เขียน CSS แบบ minify
  บรรทัดเดียวซึ่งอ่านยาก สำหรับไฟล์นี้ให้เขียนแบบจัดรูปปกติเพื่อให้แก้ต่อได้
