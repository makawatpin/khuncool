# ปฏิทินคอนเทนต์ครูในหลังบ้านแอดมิน (Teacher Content Calendar)

วันที่: 2026-08-30
สถานะ: อนุมัติดีไซน์แล้ว รอเขียนแผนการทำงาน

## ปัญหา

แอดมินไม่มีที่ให้ดูว่า "ช่วงนี้ครูไทยกำลังเสิร์ชหาอะไร" และ "ต้องเริ่มทำคอนเทนต์เมื่อไหร่ถึงจะทัน" ทุกวันนี้ต้องจำเอง ทำให้พลาดจังหวะ เช่น ลงบทความวันสุนทรภู่วันที่ 25 มิ.ย. ซึ่งสายเกินไปแล้ว เพราะครูเริ่มเสิร์ชตั้งแต่ต้นเดือน

ความต้องการไม่ได้จำกัดแค่ "วันสำคัญเพื่อทำสื่อ" แต่รวมถึงรอบงานประจำปีของครูทั้งหมดที่สร้างดีมานด์การค้นหาซ้ำทุกปี — งานเอกสาร การประเมิน การสอบระดับชาติ การแข่งขัน

## เป้าหมาย

แท็บใหม่ในหน้า `/admin` ที่เปิดมาแล้วตอบได้ทันทีว่า **ตอนนี้ต้องทำคอนเทนต์อะไร** และ **เดือนหน้ามีอะไรรออยู่**

## ขอบเขต

อ่านอย่างเดียว (read-only) ข้อมูลวันสำคัญเก็บเป็นไฟล์ในโค้ด ไม่แตะ database

**สิ่งที่ไม่ทำในเฟสนี้ (ตั้งใจตัดออก)**

- ติ๊กสถานะงาน ("ทำแล้ว / ยังไม่ทำ")
- จับคู่อัตโนมัติกับบทความที่มีอยู่ในเว็บ
- แก้ไข/เพิ่มข้อมูลผ่านหน้าเว็บ
- แจ้งเตือนทางอีเมลหรือ push

ทั้งหมดนี้เพิ่มทีหลังได้โดยไม่ต้องรื้อ เพราะ `CalendarEvent` แต่ละรายการมี `id` คงที่ไว้ใช้เป็น foreign key ในอนาคต

## สถาปัตยกรรม

แบ่งเป็น 3 ชั้น แต่ละชั้นทดสอบแยกกันได้

```
lib/teacher-calendar/          ← ข้อมูล + ตรรกะล้วน ไม่มี React ไม่มี Next
  types.ts                     นิยามชนิดข้อมูล
  events.ts                    แคตตาล็อกวันสำคัญทั้งหมด
  lunarDates.ts                ตารางวันทางจันทรคติรายปี
  resolve.ts                   แปลง occurrence → วันที่จริง + คำนวณสถานะ

app/api/admin/calendar/route.ts  ← คำนวณด้วยเวลาไทย คืน JSON

app/admin/tabs/CalendarTab.tsx   ← แสดงผล
app/admin/tabsConfig.tsx         ← เพิ่ม 1 entry
```

**เหตุผลที่แยก `lib/teacher-calendar/` ออกจาก UI:** ตรรกะการคำนวณสถานะเป็น pure function ที่รับ "วันนี้" เป็นพารามิเตอร์ ทำให้เขียนเทสต์ได้โดยไม่ต้องแกล้งเวลาระบบ และถ้าอนาคตอยากเอาปฏิทินไปแสดงหน้าบ้านให้ครูดูด้วย ก็ใช้ชั้นนี้ซ้ำได้เลย

## ชั้นที่ 1: ข้อมูล

### ชนิดข้อมูล

```ts
type CategoryKey =
  | "holiday"      // วันสำคัญ/เทศกาล
  | "paperwork"    // งานเอกสาร-ธุรการ
  | "evaluation"   // การประเมิน/วิทยฐานะ
  | "exam"         // การสอบระดับชาติ
  | "competition"  // การแข่งขัน
  | "career"       // สอบบรรจุ/ความก้าวหน้าอาชีพ
  | "term";        // จังหวะภาคเรียน

type Occurrence =
  | { kind: "fixed"; month: number; day: number }
  | { kind: "nthWeekday"; month: number; weekday: number; nth: number }
  | { kind: "lookup"; key: string }
  | { kind: "range"; startMonth: number; startDay: number; endMonth: number; endDay: number };

interface CalendarEvent {
  id: string;
  title: string;
  category: CategoryKey;
  occurrence: Occurrence;
  precision: "exact" | "approx";
  leadDays: number;
  note?: string;
  searchTerms: string[];
  contentIdeas: string[];
}
```

### คำอธิบายฟิลด์

| ฟิลด์ | ความหมาย |
|---|---|
| `id` | รหัสคงที่ ห้ามเปลี่ยน เช่น `sunthorn-phu-day` ใช้เป็น key ใน React และเป็นจุดเชื่อมกับฟีเจอร์ในอนาคต |
| `occurrence` | กติกาว่าวันนี้ตกวันไหนในแต่ละปี ดูตารางด้านล่าง |
| `precision` | `exact` = วันตรงเป๊ะทุกปี, `approx` = รู้แค่ช่วง ต้องเช็คประกาศจริง UI จะแสดงต่างกัน |
| `leadDays` | ควรเผยแพร่คอนเทนต์ล่วงหน้ากี่วัน เป็นตัวเลขที่กำหนดจากพฤติกรรมการค้นหา ไม่ใช่ค่าคงที่ทั้งระบบ |
| `note` | ข้อความเตือนแอดมิน เช่น "วันสอบจริงต้องรอประกาศจาก สทศ." |
| `searchTerms` | คำที่ครูเสิร์ชช่วงนั้น ใช้เป็นวัตถุดิบเลือกหัวข้อและทำ SEO |
| `contentIdeas` | ไอเดียคอนเทนต์ที่ควรมี เช่น "ใบงานระบายสี", "ตัวอย่าง ปพ.5 กรอกแล้ว" |

### กติกา `Occurrence` ทั้ง 4 แบบ

| แบบ | ใช้เมื่อ | ตัวอย่าง |
|---|---|---|
| `fixed` | ตรงวันเดิมทุกปี | DMC 10 มิ.ย. · วันแม่ 12 ส.ค. · วันครู 16 ม.ค. |
| `nthWeekday` | อิงลำดับวันในสัปดาห์ | วันเด็ก = เสาร์ที่ 2 ของ ม.ค. (`month: 1, weekday: 6, nth: 2`) |
| `lookup` | วันทางจันทรคติ คำนวณสูตรตรงไม่ได้ | ลอยกระทง · มาฆบูชา · วิสาขบูชา · อาสาฬหบูชา/เข้าพรรษา |
| `range` | เป็นช่วง ไม่ใช่วันเดียว | ศิลปหัตถกรรมระดับเขต · ช่วงสอบ O-NET · ปิดเทอม |

สำหรับ `range` ให้ใช้ `startMonth`/`startDay` เป็นฐานคำนวณกำหนดเผยแพร่ เพราะคอนเทนต์ต้องพร้อมก่อนช่วงเริ่ม

### ตารางวันจันทรคติ (`lunarDates.ts`)

โครงสร้าง: `Record<lunarKey, Record<year, "MM-DD">>`

ต้องกรอกข้อมูลย้อนหลังจากปฏิทินหลวงครอบคลุม **ค.ศ. 2026–2028** สำหรับ key เหล่านี้: `makha-bucha`, `visakha-bucha`, `asalha-bucha`, `khao-phansa`, `ok-phansa`, `loy-krathong`

ถ้าเรียกปีที่ไม่มีในตาราง `resolve` ต้องคืน `null` และ UI แสดงว่า "ยังไม่มีข้อมูลวันที่ของปีนี้" — **ห้ามเดาวันเอง** ปฏิทินที่บอกวันผิดแย่กว่าปฏิทินที่บอกว่าไม่รู้

### แคตตาล็อกวันสำคัญเริ่มต้น

ครอบคลุมทั้ง 7 หมวด รายการต่อไปนี้เป็นชุดขั้นต่ำที่ต้องมี เพิ่มเติมได้ในภายหลังโดยแก้ไฟล์เดียว

**หมวด `holiday` — วันสำคัญ/เทศกาล**
วันไหว้ครู (พฤหัสฯ ต้น มิ.ย.) · วันสุนทรภู่ 26 มิ.ย. · วันต่อต้านยาเสพติดโลก 26 มิ.ย. · วันภาษาไทยแห่งชาติ 29 ก.ค. · วันเฉลิมพระชนมพรรษา ร.10 28 ก.ค. · วันแม่แห่งชาติ 12 ส.ค. · วันวิทยาศาสตร์แห่งชาติ 18 ส.ค. · วันเยาวชนแห่งชาติ 20 ก.ย. · วันปิยมหาราช 23 ต.ค. · วันลอยกระทง (lookup) · วันพ่อแห่งชาติ 5 ธ.ค. · วันรัฐธรรมนูญ 10 ธ.ค. · วันขึ้นปีใหม่ 1 ม.ค. · วันเด็กแห่งชาติ (เสาร์ที่ 2 ม.ค.) · วันครู 16 ม.ค. · วันมาฆบูชา (lookup) · วันวาเลนไทน์ 14 ก.พ. · วันสตรีสากล 8 มี.ค. · วันจักรี 6 เม.ย. · วันสงกรานต์ 13–15 เม.ย. · วันวิสาขบูชา (lookup) · วันอาสาฬหบูชา/เข้าพรรษา (lookup)

`leadDays` แนะนำ: 14 วันสำหรับวันที่ทำสื่อการสอนตรง ๆ, 21 วันสำหรับวันที่มีกิจกรรม/ป้าย/การ์ดประกอบ (วันแม่ วันเด็ก วันไหว้ครู)

**หมวด `paperwork` — งานเอกสาร-ธุรการ**
ยืนยันข้อมูลนักเรียน DMC รอบ 1 (10 มิ.ย.) · DMC รอบ 2 (10 พ.ย.) · จัดทำแผนการจัดการเรียนรู้ เทอม 1 (พ.ค. `approx`) · เทอม 2 (ต.ค. `approx`) · กรอก ปพ.5 ปลายภาคเรียน 1 (ก.ย.–ต.ค. `approx`) · ปลายภาคเรียน 2 (มี.ค. `approx`) · จัดทำ SAR และประกันคุณภาพภายใน (เม.ย.–พ.ค. `approx`)

**หมวด `evaluation` — การประเมิน/วิทยฐานะ**
จัดทำข้อตกลง ว.PA ต้นปีงบประมาณ (ต.ค. `approx`) · ส่งผลลัพธ์ ว.PA ปลายปีงบประมาณ (ก.ย. `approx`) · เลื่อนขั้นเงินเดือนรอบ 1 (1 เม.ย.) · รอบ 2 (1 ต.ค.) · ประเมินครูผู้ช่วย (ทุก 6 เดือน `approx`)

**หมวด `exam` — การสอบระดับชาติ**
RT ป.1 (ก.พ. `approx`) · NT ป.3 (มี.ค. `approx`) · O-NET ป.6 · O-NET ม.3 · O-NET ม.6 (ก.พ.–มี.ค. `approx`) · สอบกลางภาค/ปลายภาคทั้งสองเทอม (`approx`)

ทุกรายการในหมวดนี้ต้องมี `note` ระบุว่าวันจริงต้องเช็คประกาศจาก สทศ. หรือต้นสังกัด

**หมวด `competition` — การแข่งขัน**
งานศิลปหัตถกรรมนักเรียนระดับเขตพื้นที่ (ส.ค.–ก.ย. `approx`) · ระดับชาติ (ธ.ค.–ก.พ. `approx`)

**หมวด `career` — สอบบรรจุ/ความก้าวหน้าอาชีพ**
สอบครูผู้ช่วย รอบทั่วไป (`approx`) · สอบ ก.พ. ภาค ก (`approx`) · ต่ออายุใบประกอบวิชาชีพครู (`approx`)

**หมวด `term` — จังหวะภาคเรียน**
เปิดภาคเรียนที่ 1 (16 พ.ค.) · ปิดภาคเรียนที่ 1 (ต.ค. `approx`) · เปิดภาคเรียนที่ 2 (พ.ย. `approx`) · ปิดภาคเรียนใหญ่ (เม.ย. `approx`)

## ชั้นที่ 2: ตรรกะ (`resolve.ts`)

ทุกฟังก์ชันเป็น pure รับ "วันนี้" เป็นพารามิเตอร์ ไม่เรียก `new Date()` ข้างใน

### `resolveDate(occurrence, year): ResolvedDate | null`

แปลงกติกาเป็นวันที่จริงของปีที่ระบุ คืน `null` เมื่อเป็น `lookup` ที่ไม่มีข้อมูลปีนั้น

### `computeStatus(event, resolved, today): EventStatus`

```
publishBy = eventDate − leadDays
```

| สถานะ | เงื่อนไข |
|---|---|
| `passed` | `today > eventDate` |
| `overdue` | `today > publishBy` |
| `act-now` | `publishBy − today ≤ 14 วัน` |
| `upcoming` | นอกจากนั้น |
| `unknown` | `resolveDate` คืน `null` |

ตรวจตามลำดับนี้จากบนลงล่าง

### `buildAgenda(events, today, monthsAhead): AgendaItem[]`

รวมทุกรายการ คำนวณวันของปีปัจจุบันและปีถัดไป (เพื่อให้รายการเดือน ม.ค.–เม.ย. โผล่ตอนอยู่ปลายปี) กรอง `passed` ออก แล้วเรียงตามวันที่ควรเผยแพร่จากใกล้ไปไกล

## ชั้นที่ 3: API (`app/api/admin/calendar/route.ts`)

ทำตามแพตเทิร์นเดียวกับ `app/api/admin/content/route.ts` — เรียก `requireAdmin(request)` ก่อนเสมอ คืน 401/403 ตามผลลัพธ์

**เหตุผลที่ต้องผ่าน API ทั้งที่ข้อมูลเป็น static:** สถานะขึ้นกับ "วันนี้" ถ้าคำนวณฝั่ง client จะเพี้ยนตาม timezone และนาฬิกาเครื่องแอดมิน คำนวณฝั่งเซิร์ฟเวอร์ด้วยเขตเวลา `Asia/Bangkok` ครั้งเดียวจึงถูกต้องเสมอ และยังเข้ากับแพตเทิร์น `useAdminFetch` ของแท็บอื่น

รับ query parameter `month` (รูปแบบ `YYYY-MM`) สำหรับเลื่อนดูเดือนอื่นในตาราง ถ้าไม่ส่งมาให้ใช้เดือนปัจจุบัน

รูปแบบผลลัพธ์:

```ts
{
  today: string;          // "2026-08-30" เวลาไทย
  agenda: AgendaItem[];   // รายการเรียงตามความเร่งด่วน
  month: {
    year: number;
    month: number;
    days: { date: string; items: AgendaItem[] }[];
  };
}
```

`AgendaItem` = `CalendarEvent` + `resolvedDate` + `publishByDate` + `status` + `daysUntilEvent` + `daysUntilPublishBy`

ต้องไม่ throw เมื่อเจอ `lookup` ที่ไม่มีข้อมูล — รายการนั้นได้สถานะ `unknown` และยังคงอยู่ในผลลัพธ์

## ชั้นที่ 4: หน้าจอ (`CalendarTab.tsx`)

ใช้ `useAdminFetch` + `ErrorCard` + `ListSkeleton` เหมือนแท็บอื่นทุกประการ ภาษาไทยทั้งหมด ใช้ design token ที่มีอยู่ (`--radius-card`, `border-border`, `bg-surface-card`, `text-ink-muted`)

### ส่วนบน — ไทม์ไลน์ "ต้องทำตอนนี้"

แสดง 5 รายการแรกจาก `agenda` แต่ละแถวประกอบด้วย

- จุดสีสถานะ + ป้ายข้อความ (เลยกำหนดลงแล้ว / ถึงเวลาเริ่มทำ / ยังไม่ถึงเวลา)
- ชื่อวัน + หมวด
- วันที่จริง และ "เหลืออีก N วัน" — ถ้า `precision` เป็น `approx` ให้เติมคำว่า "ราว" นำหน้าวันที่ และแสดงไอคอนที่ hover แล้วเห็น `note`
- กำหนดเผยแพร่ที่ควรเป็น

กดแถวเพื่อขยาย เห็น `searchTerms` (แสดงเป็น chip) และ `contentIdeas` (แสดงเป็นรายการ)

**สีสถานะ:** `overdue` แดง · `act-now` เหลือง/ส้ม · `upcoming` เทา · `unknown` เทาพร้อมไอคอนคำถาม

### ส่วนล่าง — ตารางเดือน

ตาราง 7 คอลัมน์ เริ่มวันจันทร์ มีปุ่มเลื่อนเดือนก่อนหน้า/ถัดไป และปุ่มกลับมาเดือนปัจจุบัน

แต่ละช่องวันแสดงจุดสีตามหมวด (สูงสุด 3 จุด เกินกว่านั้นแสดง `+N`) วันนี้มีกรอบเน้น กดที่ช่องแล้วรายละเอียดของวันนั้นแสดงใต้ตาราง

มีแถวปุ่มกรองหมวดทั้ง 7 อยู่เหนือตาราง กดสลับเปิด/ปิดได้ ค่าเริ่มต้นเปิดทั้งหมด การกรองทำฝั่ง client จากข้อมูลที่ได้มาแล้ว

### สถานะว่าง

ถ้า `agenda` ว่าง แสดงข้อความว่าไม่มีรายการที่ต้องเตรียมในช่วงนี้ ไม่ใช่หน้าจอเปล่า

### เพิ่มใน `tabsConfig.tsx`

```
key: "calendar"
label: "ปฏิทิน"
description: "วันสำคัญและกำหนดลงคอนเทนต์"
Icon: CalendarIcon   // วาด svg ขนาด 16 viewBox 18 ให้เข้าชุดกับไอคอนเดิม
```

วางไว้ระหว่าง `content` กับ `system`

## การทดสอบ

ตรรกะทั้งหมดอยู่ใน pure function จึงทดสอบตรงได้ กรณีที่ต้องครอบคลุม

- `resolveDate` ทั้ง 4 แบบ รวมกรณี `nthWeekday` ที่วันแรกของเดือนตรงกับวันที่ต้องการพอดี
- `range` ที่คร่อมปีใหม่ (ศิลปหัตถกรรมระดับชาติ ธ.ค.–ก.พ.)
- `lookup` ที่ไม่มีข้อมูลปีนั้น ต้องคืน `null` ไม่ throw
- `computeStatus` ที่ขอบเขตแต่ละสถานะ รวมวันที่ตรงกับ `publishBy` พอดี
- `buildAgenda` ต้องมีรายการต้นปีถัดไปโผล่เมื่อ "วันนี้" อยู่ปลายปี

## ความเสี่ยงที่รู้ตัว

**ข้อมูลค้าง** — ตารางจันทรคติหมดอายุปี 2028 ต้องกลับมาเติม ระบบจะแสดงสถานะ `unknown` เตือนเองเมื่อถึงเวลา ไม่เงียบหาย

**`leadDays` เป็นการประมาณ** — ตัวเลขมาจากการคาดการณ์พฤติกรรมการค้นหา ไม่ได้มาจากข้อมูลจริง ควรปรับตามสถิติที่เก็บได้ในอนาคต ถือเป็นค่าตั้งต้นที่แก้ง่ายเพราะอยู่ในไฟล์เดียว

**วันที่ `approx` หลายรายการ** — โดยเฉพาะหมวดสอบและการแข่งขัน ต้องแสดงให้ชัดว่าไม่ใช่วันยืนยัน มิฉะนั้นแอดมินจะวางแผนผิด
