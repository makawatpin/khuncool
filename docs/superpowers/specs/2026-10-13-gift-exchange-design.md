# จับฉลากแลกของขวัญ (/gift-exchange) — Design

วันที่: 2026-10-13
สถานะ: อนุมัติดีไซน์แล้ว รอผู้ใช้ตรวจ spec ก่อนเขียนแผน implement

## 1. เป้าหมาย

เครื่องมือหน้าชั้นเรียนสำหรับกิจกรรมจับฉลากแลกของขวัญปีใหม่ ฉายขึ้นจอ
โปรเจกเตอร์แล้วให้นักเรียนออกมาเปิดกล่องของขวัญบนจอทีละคนแบบ **ห่วงโซ่**:
คนที่เปิดกล่องเจอชื่อใคร ก็มอบของให้คนนั้นต่อหน้าห้อง แล้วคนนั้นออกมาเปิด
กล่องเป็นคนถัดไป จนกล่องสุดท้ายวนกลับมาที่คนแรก

แก้ปัญหาจับฉลากกระดาษ (จับได้ชื่อตัวเอง ต้องจับใหม่ วุ่นวาย) และเปลี่ยน
การแลกของให้เป็นการแสดงที่ทั้งห้องลุ้นไปด้วยกัน

จุดขายคือ **ฉากเปิดกล่องที่อลังการ** — เด็กเห็นแล้วต้องว้าว: กล่องสั่น
แสงรั่ว ฝาระเบิด คอนเฟตตี ชื่อเด้งออกมา พร้อมเสียงประกอบและเพลง

ช่วงใช้งานจริงคือปลายพฤศจิกายน–ธันวาคม ควรขึ้นเว็บภายในต้นพฤศจิกายน
เพื่อให้ Google index ทันฤดูกาล

### ไม่อยู่ในขอบเขต (YAGNI)

- ไม่มีคู่ห้ามเจอ (exclusion pairs)
- ไม่มีโหมดลับ / ส่งผลส่วนตัว / พิมพ์ใบผลจับคู่
- ไม่มีโหมด "ส่งต่อของขวัญ" แบบสุ่มหยิบของจากกอง
- ไม่มีการซิงก์ขึ้น Supabase (ยกเว้น usage event ผ่าน `trackToolEvent`)
- ไม่ให้ครูเลือกคนเริ่มเอง — สุ่มเสมอ

## 2. Flow บนจอ

### จอ 1 — ตั้งค่า (`phase: "setup"`)

- ช่อง textarea วางรายชื่อ บรรทัดละคน (ตัดช่องว่างหัวท้าย ข้ามบรรทัดว่าง)
- ปุ่ม `📚 ห้องเรียน` ใช้ `components/ClassroomRosterPicker.tsx` ดึงรายชื่อ
  จากห้องเรียนที่บันทึกไว้ (แทนที่รายชื่อในช่อง)
- รายชื่อแสดงเป็นชิป กดสลับ "มา / ขาด" ได้ คนขาดแสดงจางและขีดฆ่า
- ชื่อซ้ำกันได้ (เด็กชื่อเล่นซ้ำกันเป็นเรื่องปกติ) — ระบบแยกด้วย `id`
  ไม่ใช่ชื่อ แต่ชิปแสดงเลขต่อท้ายเมื่อชื่อซ้ำ เช่น "ต้น (2)"
- ต้องมีคนที่ "มา" อย่างน้อย 3 คน ปุ่ม "เริ่มจับฉลาก" จึงจะกดได้
  (2 คนแลกกันเองไม่ต้องใช้เครื่องมือ) แสดงข้อความบอกเหตุผลเมื่อไม่ถึง
- ปุ่มเปิด/ปิดเสียง
- ถ้ามีเกมค้างใน localStorage แสดงแบนเนอร์ด้านบน:
  "มีเกมค้างอยู่ (เปิดไปแล้ว 12/30) — [เล่นต่อ] [เริ่มใหม่]"
  "เริ่มใหม่" ล้างความคืบหน้าแต่คงรายชื่อไว้

### จอ 2 — สุ่มคนเริ่ม (`phase: "starter"`)

- ชื่อวิ่งแบบสล็อตแมชชีน ~3 วินาที เร็วแล้วค่อยๆ ช้าลง เสียงติ๊กทุกชื่อ
- หยุดที่คนหนึ่ง (สุ่มจากคนที่มา) พร้อมเสียงแฟนแฟร์และคอนเฟตตีเล็ก:
  "🎉 ต้น เริ่มก่อน!"
- ปุ่ม "ไปที่กล่องของขวัญ" → จอ 3
- ผลการสุ่มบันทึกทันทีที่สุ่มเสร็จ (ก่อนแอนิเมชันจบ) ถ้ารีเฟรชตอนนี้ กลับมา
  จะเจอคนเริ่มเดิม ไม่สุ่มใหม่

### จอ 3 — เวทีหลัก (`phase: "stage"`, วนซ้ำ)

- กล่องของขวัญใบใหญ่กลางจอ หัวจอ "ตาของ **ต้น** — แตะกล่องเลย!"
- กดกล่อง (หรือ Space / Enter เมื่อกล่องโฟกัสอยู่) → ฉากเปิดกล่อง (ข้อ 3)
- หลังเผยชื่อ: "ต้น 🎁 → ฝน" และปุ่ม "ต่อไป: ตาของ ฝน"
- แถบโซ่ด้านล่าง: ชิปชื่อเรียงตามลำดับที่ผ่านมา (ต้น → ฝน → …) เลื่อนแนวนอน
  ให้คนล่าสุดอยู่ในจอเสมอ
- ตัวนับ "เหลือ N คน" (N = คนที่มาและยังไม่ถูกเผย)
- ปุ่มเล็ก `👥 รายชื่อ` เปิดแผงจัดการกลางเกม:
  - ติ๊กคนขาดออก / ติ๊กกลับเข้ามา — ทำได้เฉพาะคนที่ยังไม่อยู่ในโซ่
  - เพิ่มชื่อคนมาสาย
  - คนที่อยู่ในโซ่แล้วแสดงล็อกไว้ พร้อมคำอธิบายสั้นๆ ว่าทำไมแก้ไม่ได้
- ปุ่มเต็มจอ (`useToolFullscreen`), ปุ่มเสียง, ปุ่ม "จบเกม / กลับไปตั้งค่า"
  (ถามยืนยันก่อน)

### จอ 4 — ปิดวง (`phase: "finale"`)

- กล่องใบสุดท้ายเป็นฉากพิเศษ (ข้อ 3) เผยชื่อคนแรก: "กลับมาที่ ต้น! ครบวงแล้ว 🎉"
- ต่อด้วยภาพวงกลม: ชื่อทุกคนเรียงรอบวง เส้นเชื่อมวาดไล่ทีละคนตามลำดับโซ่
  พร้อมหัวลูกศร แล้วดอกไม้ไฟเต็มจอ
- ถ้าเกิน ~30 คน ชื่อในวงย่อขนาดตัวอักษรลงให้พอดี (ไม่ซ้อนกัน)
- ปุ่ม "เริ่มใหม่ (รายชื่อเดิม)"

## 3. ฉากเปิดกล่อง

### เวที

- พื้นหลังไล่สีกรมท่าเข้ม → ม่วง มีหิมะ/ประกายไฟลอยช้าๆ ตลอด (CSS ล้วน
  จำนวนอนุภาคคงที่ ~30 ชิ้น)
- สปอตไลต์ส่องลงที่กล่อง (radial gradient)
- กล่องเป็น **SVG แยกชิ้น**: ตัวกล่อง ฝา ริบบิ้นแนวตั้ง/แนวนอน โบว์
  แต่ละชิ้นเป็น `<g>` ที่ขยับแยกได้ มีไล่สี เงา และแสงวาววิ่งผ่าน
- สีกล่องเปลี่ยนทุกตา วนจากชุดสี 6 ชุด (ตัวกล่อง + ริบบิ้นคู่สีกัน)
  เลือกตาม `chain.length % 6` เพื่อให้รีเฟรชแล้วสีเดิม

### ลำดับเวลา (ตาปกติ ~4.5 วินาที)

| เวลา | ภาพ | เสียง |
|---|---|---|
| รอ | กล่องลอยขึ้นลงเบาๆ ประกายวิบวับรอบกล่อง | เพลงวนเบาๆ |
| 0–2.0s ลุ้น | กล่องสั่นแรงขึ้นเรื่อยๆ ขยาย 1.0→1.15 แสงรั่วตามรอยต่อฝา จอรอบๆ มืดลง | เพลงหรี่ลง กลองรัวเร่งขึ้น |
| 2.0s ระเบิด | ริบบิ้นขาดกระเด็น ฝาพุ่งหมุนออกนอกจอ ลำแสงพุ่งขึ้น แฟลชขาว 120ms คอนเฟตตีระเบิดสองฝั่ง | "ปัง!" |
| 2.2–3.2s เผยชื่อ | ชื่อตัวใหญ่ไล่สีทองเด้งขึ้นจากกล่อง (overshoot) ดาวแตกกระจายรอบชื่อ | แตรเฉลิมฉลอง |
| 3.2–4.5s | "ต้น 🎁 → ฝน" fade ขึ้น ปุ่ม "ต่อไป" ปรากฏ | เพลงกลับมาดังปกติ |

- ระหว่างแอนิเมชัน (0–3.2s) กดซ้ำไม่มีผล
- **ผลถูกสุ่มและบันทึกลง state + localStorage ตอนกดกล่อง (t=0)** ไม่ใช่ตอน
  แอนิเมชันจบ — ถ้ารีเฟรชกลางฉาก กลับมาจะเห็นผลเดิมที่เผยแล้ว ไม่สุ่มใหม่

### กล่องใบสุดท้าย

- กล่องสีทอง ลุ้นนานขึ้น (~3s) ฝาระเบิดพร้อมดอกไม้ไฟ เผยชื่อคนแรก
  แล้วเข้าจอ 4

### เสียง (`useGiftSound.ts`)

WebAudio ล้วน ไม่มีไฟล์เสียง ตามแบบ `app/mystery-board/useBoardSound.ts`

- เพลงวน: ทำนองปีใหม่/คริสต์มาสสไตล์ chiptune สร้างเป็น `AudioBuffer`
  ครั้งเดียว เล่นวนที่ volume ต่ำ ต้องเป็นทำนองที่แต่งเอง ไม่ใช้เพลงที่มี
  ลิขสิทธิ์
- เอฟเฟกต์: `tick` (สล็อต), `fanfare` (ได้คนเริ่ม), `drumroll` (ลุ้น, ยาวตาม
  ระยะลุ้น), `pop` (ระเบิด), `celebrate` (เผยชื่อ), `finale` (ปิดวง)
- เพลงหรี่ลงอัตโนมัติ (duck) ระหว่างกลองรัว
- ปุ่มเสียงปิดทั้งเพลงและเอฟเฟกต์; สถานะเก็บใน localStorage
- AudioContext ปลดล็อกจาก gesture แรกของผู้ใช้ (ปุ่มเริ่ม) ตามแบบเดิม

### การเข้าถึง

- `prefers-reduced-motion: reduce` → ตัดการสั่น แฟลช ฝาพุ่ง และอนุภาค
  เหลือ fade/scale เบาๆ; ลำดับเวลาสั้นลงเหลือ ~1.5s; เสียงยังเล่นตามปกติ
- ชื่อที่เผยประกาศผ่านภูมิภาค `aria-live="polite"`: "ต้น มอบของขวัญให้ ฝน"
- กล่องเป็น `<button>` มี `aria-label` "เปิดกล่องของขวัญของ ต้น"
- แฟลชขาวไม่กะพริบซ้ำ (ครั้งเดียว ≤ 120ms) เพื่อไม่ให้เสี่ยงต่อผู้ที่ไวต่อแสง

## 5. โมเดลข้อมูลและ logic (`chainModel.ts`)

```ts
type Player = { id: string; name: string; active: boolean };

type Phase = "setup" | "starter" | "stage" | "finale";

type GameState = {
  version: 1;
  players: Player[];
  chain: string[];   // id ตามลำดับที่ถูกเผย; chain[0] = คนเริ่ม
  phase: Phase;
  soundOn: boolean;
};
```

**นิยาม:**

- `giver(state)` = `chain.at(-1)` — คนที่ถึงตาเปิดกล่อง
- `pool(state)` = ผู้เล่นที่ `active` และ `id` ไม่อยู่ใน `chain`
- `remaining(state)` = `pool(state).length`

**ฟังก์ชัน (pure ทั้งหมด รับ `rng: () => number` เพื่อทดสอบได้):**

- `createPlayers(names: string[]): Player[]` — สร้าง id ใหม่ ทุกคน `active: true`
- `canStart(state)` — คน active ≥ 3
- `pickStarter(state, rng)` → state ที่ `chain = [id]`, `phase: "starter"`
- `openBox(state, rng)` → `{ state, receiverId, closesLoop }`
  - ถ้า `pool` ไม่ว่าง: สุ่ม 1 คนจาก pool ต่อท้าย `chain`
  - ถ้า `pool` ว่าง: `receiverId = chain[0]`, `closesLoop: true`, `phase: "finale"`
    (ไม่ต่อท้าย chain)
- `setActive(state, id, active)` — ปฏิเสธ (คืน state เดิม) ถ้า `id` อยู่ใน
  `chain` แล้ว
- `addPlayer(state, name)` — เพิ่มคนใหม่ `active: true` ใช้ได้ทุก phase ก่อน
  finale
- `reset(state)` — `chain = []`, `phase: "setup"` คงรายชื่อ
- `load(raw: unknown): GameState | null` / `serialize(state): string`
  — `load` คืน `null` ถ้า JSON เสีย, `version` ไม่ใช่ 1, หรือโครงสร้างผิด
  (เช่น `chain` อ้าง id ที่ไม่มีใน `players`)

**ทำไมสุ่มทีละกล่องแทนการจับคู่ล่วงหน้า:** การต่อท้ายด้วยคนที่สุ่มแบบ
สม่ำเสมอจาก pool ทีละครั้งให้ผลเป็นวงเดียว (single cycle) ที่สุ่มเท่ากันทุก
แบบ เหมือนการสุ่ม permutation ของคนที่เหลือ — ไม่มีใครได้ตัวเอง และไม่มี
วงย่อย (ซึ่งการสุ่มแบบ derangement ธรรมดาเกิดได้ และจะทำให้โซ่ขาด)
และยังเปิดให้แก้รายชื่อกลางเกมได้

**ขั้นต่ำและกรณีติ๊กขาดกลางเกม:** ต้องมีคน active ≥ 3 ตอนเริ่ม (2 คนแลกกัน
เองไม่ต้องใช้เครื่องมือ) ระหว่างเกม ถ้าครูติ๊กขาดจน pool ว่าง ก็แค่ปิดวงเร็ว
ขึ้น ไม่ผิดกติกา ตราบใดที่ `chain.length ≥ 2` กรณีเดียวที่ผิดคือ chain ยาว 1
แล้ว pool ว่าง (คนเริ่มจะได้ตัวเอง) — `setActive` จึงต้องปฏิเสธการติ๊กคน
สุดท้ายใน pool ออกเมื่อ `chain.length === 1`

**Persistence:** `localStorage["khuncool.giftexchange"]` เก็บ `GameState`
ทั้งก้อน เขียนทุกครั้งที่ state เปลี่ยน (ไม่ debounce — เปลี่ยนไม่บ่อย)
ทุกการอ่าน/เขียนครอบ try/catch; อ่านไม่ได้ = เริ่มจอ setup ว่าง

ตอนโหลดหน้า: ถ้า state ที่โหลดได้มี `phase` เป็น `starter`/`stage`/`finale`
→ อยู่ที่จอ setup พร้อมแบนเนอร์เกมค้าง; "เล่นต่อ" ไปที่ phase นั้น โดยจอ 3
แสดงผลล่าสุดที่เผยแล้วในสถานะ "เปิดแล้ว" (ไม่เล่นแอนิเมชันซ้ำ)

## 6. การจัดการข้อผิดพลาด / กรณีขอบ

- รายชื่อว่างหรือ < 3 คน → ปุ่มเริ่มปิด พร้อมข้อความ
- WebAudio ใช้ไม่ได้ → เล่นเงียบ ไม่ error
- localStorage ใช้ไม่ได้ (โหมดส่วนตัว) → เล่นได้ปกติ แค่รีเฟรชแล้วหาย
- ชื่อยาวมาก → ตัดด้วย ellipsis ในชิป/วงกลม แต่ฉากเผยชื่อย่อขนาดตัวอักษร
  ให้พอดีความกว้างจอ (ไม่ตัด)
- ห้องใหญ่ (สูงสุดที่ทดสอบ 50 คน) — แถบโซ่เลื่อนได้ วงกลมย่อตัวอักษร

## 7. การทดสอบ

**Vitest (`chainModel.test.ts`)** ด้วย rng แบบกำหนดผลได้:

- เล่นจนจบ: ทุกคนที่ active ปรากฏใน chain ครั้งเดียว และกล่องสุดท้ายคืน `chain[0]`
- ไม่มีใครได้ตัวเอง (ตรวจทุกคู่ติดกันใน chain + คู่ปิดวง)
- สุ่มหลายพันรอบด้วย `Math.random`: ทุกวงเป็นวงเดียวครอบทุกคน
- ติ๊กขาดคนใน pool กลางเกม → ไม่ถูกเผย; ติ๊กคนใน chain → ถูกปฏิเสธ
- กันติ๊กคนสุดท้ายใน pool ออกเมื่อ chain ยาว 1
- เพิ่มคนกลางเกม → ถูกเผยก่อนปิดวง
- `canStart` กับ 2 / 3 คน
- `load` กับ JSON เสีย, version ผิด, chain อ้าง id ไม่มี → `null`
- round-trip `serialize` → `load` ได้ state เท่าเดิม
