# กติกาการทำ responsive ของสื่อ /media

ทุกเกมใน `/media` ต้องทำตาม 4 ข้อนี้ ระบบกลางอยู่ที่ [`app/media/_stage/`](../app/media/_stage/)

---

## 1. ตัวเกมห้ามรู้จัก viewport

**ห้าม** ใช้ `vw`, `vh`, `dvh`, `window.innerWidth`, `matchMedia` ในโค้ดหรือ CSS ของตัวเกม

**ให้ใช้** `cqi` (ตามความกว้างเวที), `cqb` (ตามความสูงเวที), `%`, และ token จากข้อ 3

เหตุผล: เกมตัวเดียวกันต้องแสดงผลถูกต้องทั้งตอนอยู่ในคอลัมน์หน้าเว็บ ตอนเต็มจอ และตอนถูกฝังใน embed — ทั้งสามกรณีมี viewport เท่ากันแต่เวทีคนละขนาด

มีที่เดียวที่อ่าน viewport ได้คือ `.kc-stage` ใน `stage.css` เพราะการตัดสินว่าจะให้เกม "ได้พื้นที่เท่าไร" เป็นเรื่องของหน้าเว็บ ไม่ใช่ของเกม

## 2. โครงสร้าง 2 ชั้น

```tsx
const { stageProps, isFull, toggle } = useStage<HTMLDivElement>();

<div {...stageProps} className="kc-stage">
  <div className={`kc-stage-body ${styles.lab}`}>
    …เกม…
  </div>
</div>
```

- `.kc-stage` — กำหนดขนาดเวที เป็น container (`container: kcstage / size`) และเป็นตัวที่เข้าเต็มจอ
- `.kc-stage-body` — ถือ token และเป็นตัวที่ container query เข้าถึงได้

ต้องมี 2 ชั้นเพราะ container query แต่งได้เฉพาะ**ลูก**ของ container ไม่ใช่ตัว container เอง

## 3. ใช้ token ตาม "ทรง" ไม่ใช่ตามชนิดอุปกรณ์

`stage.css` ให้ token 3 ชุดตามรูปทรงของเวที ณ ขณะนั้น

| ทรง | เงื่อนไข | เกิดขึ้นเมื่อ |
|---|---|---|
| **wide** (ค่าตั้งต้น) | อื่นๆ ทั้งหมด | เดสก์ท็อป, โปรเจกเตอร์, แท็บเล็ตแนวนอน |
| **portrait** | `aspect-ratio < 0.9` | มือถือแนวตั้ง, เต็มจอแนวตั้ง |
| **short** | `aspect-ratio >= 0.9` และ `height < 440px` | มือถือแนวนอน, หน้าต่างเตี้ย |

Token ที่มี: `--kc-tap`, `--kc-pad`, `--kc-gap`, `--kc-radius`, `--kc-fs-display`, `--kc-fs-title`, `--kc-fs-head`, `--kc-fs-body`, `--kc-fs-label`

ขนาดตัวอักษรทุกตัวเป็น `max(พื้น, สัมพัทธ์)` เพราะเวทีอาจ "ทรงกว้างแต่เล็ก" ได้ (มือถือแนวนอน, แท็บเล็ตแนวตั้ง) ถ้าใช้สัมพัทธ์ล้วนตัวอักษรจะเหลือ 9px

ปุ่มที่ใส่ `className="kc-tap"` จะได้ `min-width`/`min-height` เท่า `--kc-tap` อัตโนมัติ (40px ทรงกว้าง, 44px ทรงเตี้ย, 48px ทรงตั้ง)

## 4. เต็มจอ = ขยายเวที ไม่ใช่ย่อ–ขยายภาพ

ใช้ `useStage()` เท่านั้น ห้ามเขียน `requestFullscreen` เอง ห้ามใช้ `transform: scale()` เพื่อให้พอดีจอ

`useStage` ใส่ `data-fullscreen` ให้ `.kc-stage` ทั้งกรณี native fullscreen และกรณี fallback (iOS Safari ไม่มี Fullscreen API สำหรับ `<div>`) เวทีจึงกลายเป็น `100vw × 100dvh` แล้วทุกอย่างข้างในคำนวณใหม่เองจาก container query

ผลพลอยได้: **การหมุนจอขณะเต็มจอทำงานเองโดยไม่ต้องเขียนโค้ดเพิ่ม** เพราะไม่มีค่าขนาดไหนถูกจำไว้ตั้งแต่ตอนกดเต็มจอ

## Checklist ก่อนส่งเกมใหม่

ทดสอบ 12 ช่อง — 3 อุปกรณ์ × 2 แนว × 2 โหมด (ในหน้า / เต็มจอ)

- [ ] 375×812 มือถือแนวตั้ง — ในหน้า / เต็มจอ
- [ ] 844×390 มือถือแนวนอน — ในหน้า / เต็มจอ
- [ ] 768×1024 แท็บเล็ตแนวตั้ง — ในหน้า / เต็มจอ
- [ ] 1024×768 แท็บเล็ตแนวนอน — ในหน้า / เต็มจอ
- [ ] 1280×800 เดสก์ท็อป — ในหน้า / เต็มจอ
- [ ] 1920×1080 โปรเจกเตอร์ — ในหน้า / เต็มจอ

ทุกช่องต้องผ่าน:
- [ ] ไม่มีปุ่มหรือข้อความหลุดออกนอกกรอบเวทีโดยเลื่อนไปหาไม่ได้
- [ ] ไม่มีตัวอักษรเล็กกว่า 11px
- [ ] ไม่มีเป้าแตะเล็กกว่า **24×24px** (WCAG 2.2 · 2.5.8 Target Size Minimum) — ข้อนี้คือเกณฑ์ตก
- [ ] หน้าเว็บไม่เลื่อนแนวนอน (`documentElement.scrollWidth === innerWidth`)
- [ ] หมุนจอขณะเต็มจอแล้ว layout เปลี่ยนตามทันที

`--kc-tap` (40/44/48 ตามทรง) เป็นเป้าหมาย**ความสบายมือ** ตาม Apple HIG / Material ไม่ใช่เกณฑ์ตก — ปุ่มหลักที่อยู่โดดๆ (เริ่ม, เต็มจอ, ถัดไป, slider) ควรถึงค่านี้ ส่วนตารางตัวเลือกที่ปุ่มติดกันเป็นแผงยอมให้ต่ำกว่าได้ สคริปต์จะรายงานไว้ในช่อง `belowComfortTargets` แยกจากผลตก

สคริปต์วัดอัตโนมัติ: [`scripts/audit-stage.js`](../scripts/audit-stage.js)
