### ข้อ 3 คือบั๊กที่รุนแรงที่สุดของทั้งเฟส และเกือบหลุดไป

`.cardArea` เป็น flex `align-items:center` + `overflow:visible` การ์ดคำถามสูง 189px แต่พื้นที่ได้ 46px
ส่วนเกิน 66px ไปนั่งทับแถวปุ่มที่สูง 64px = **ปุ่ม IS/ARE ถูกคลุมมิด กดไม่ได้เลย** (คลิก 12 ครั้ง progress ค้าง 1/12)

การ์ดสูง 189px เพราะทุกมิติวัดจาก **`cqi` (ความกว้าง)** บนเวทีที่กว้าง 780px แต่เตี้ย 304px —
กับดักที่ contract เขียนเตือนไว้ ตัวเดียวกับที่เจอในหัวเรื่อง intro ของ motion-lab

**ไม่มี check ไหนในระบบเห็นได้** — ปุ่มอยู่ในเวที ไม่ถูก clip ขนาดเต็ม ผ่านทุกเกณฑ์ที่มี แค่ถูกทับ

> **ช่องว่างที่ยังอยู่:** audit ยังไม่มี check สำหรับ "control ถูก element อื่นทับ"
> ตอนนี้พึ่งการที่ `clickFirst` ไม่ใช้ force แล้ว Playwright จะฟ้องพร้อมชื่อ element ที่ขวาง —
> แต่ครอบเฉพาะเกมที่มี walk เท่านั้น เกมที่ไม่มี walk ยังตรวจไม่ได้

### ลองเขียน check ตัวนี้แล้ว — ยังใช้ไม่ได้ อย่าทำซ้ำแบบเดิม

แนวคิดตรงไปตรงมาคือยิง `elementFromPoint` ที่จุดกึ่งกลางทุกปุ่ม แล้วดูว่าได้ปุ่มนั้นกลับมาไหม
**เขียนแล้ว ทดสอบแล้ว ใช้ไม่ได้** — บันทึกไว้เพื่อไม่ให้รอบหน้าเสียเวลาซ้ำ:

1. รอบแรกได้ **312 แถว** ซึ่ง **85% เป็น modal บังปุ่มข้างหลัง** = พฤติกรรมที่ถูกต้อง ไม่ใช่บั๊ก
2. ใส่ตัวกรอง 3 ชั้น (modal / ปุ่มนอกเวที / `NEXTJS-PORTAL` ของ dev server) เหลือ **35 แถว**
3. **ตัวกรอง modal กินบั๊กจริงทิ้งด้วย** — `.kc-stage-body` เป็น `position:absolute; inset:0`
   อยู่แล้วโดยนิยาม ทุก element เลยเข้าเงื่อนไข "อยู่หลัง modal" check เงียบทั้งระบบ
   (จับได้เพราะทดสอบ 2 ทิศทาง: ของที่แก้แล้วต้องเงียบ **และ** ของที่ใส่บั๊กกลับต้องดัง)
4. แก้ตัวกรองแล้วรันจริง — **35 แถวที่เหลือ ไม่มีอันไหนเป็นบั๊กจริงเลยสักอัน**
   ทดสอบด้วยการกดจริงทั้ง density-lab, talk-card, math-bomb — กดติดหมดทุกตัว

**สาเหตุที่ล้มเหลว:** harness รีเซ็ต `scrollTop` ทุก element เป็น 0 ก่อนวัด (จำเป็นสำหรับ check อื่น
ทั้งหมด — ดู contract §6) แต่ผู้ใช้จริง**เลื่อนไปหาปุ่มที่จะกด** วัดที่ density-lab ได้ชัด:

```
ที่ audit วัด        : slider y=624 → elementFromPoint ได้ tankArea
หลัง scrollIntoView  : slider y=593 → ได้ INPUT ถูกตัว
```

"ถูกทับที่ scroll 0" ≠ "กดไม่ได้" — ส่วน is-are-sorting ต่างออกไปจริงๆ เพราะการ์ดทับปุ่มโดยไม่เกี่ยวกับ
scroll เลย (Playwright เลื่อนให้แล้วยังปฏิเสธ)

**ถ้าจะทำให้ถูก** ต้องเลื่อน control เข้ามาในจอก่อนแล้วค่อย hit-test ซึ่งขัดกับการรีเซ็ต scroll ที่ check
อื่นต้องพึ่ง — แปลว่าต้องแยกเป็น pass ต่างหาก ไม่ใช่ยัดเข้าไปใน `auditStage()`

## 8. ข้อจำกัดที่ยังอยู่ (รู้ตัว ไม่ใช่ลืม)

### วัดจาก headless viewport ตายตัว

`dvh` บนมือถือจริงขยับตามแถบ URL ที่ซ่อน/โผล่ เวทีจริงจึงอาจสูงกว่าที่วัดได้เล็กน้อย
เคสที่คับที่สุดตอนนี้คือ family-tree `plant-tree` (เป้าแตะ 26px) กับ matching (25px)
ทั้งคู่เหลือ margin เหนือเกณฑ์ 24px แค่ 1–2px — **ควรลองบนเครื่องจริงสักรอบ** (ยังไม่ได้ลอง)

### harness ยังพึ่ง sleep คงที่

ทุกจังหวะรอใช้ `waitForTimeout` ค่าคงที่ ไม่ได้รอเงื่อนไขจริง — warmup ของ sound-wheel อย่างเดียว
นอน 5400ms × 12 = 65 วิต่อขนาด และเคยวัดพลาดมาแล้วครั้งหนึ่ง (วัดตอน explode keyframe ยังไม่จบ
ทำให้การ์ดพองไป 45% ต้องขยับเป็น 2500ms) เปลี่ยนไปรอเงื่อนไข (`toBeVisible`) จะเร็วกว่าและ
ตัดบั๊กประเภทนี้ทิ้งทั้งกลุ่ม แทนที่จะไล่จูนค่าคงที่ทีละครั้งที่โดน

### จุดเปราะใน harness ที่รายงานไว้แต่ยังไม่แก้

- solver ของ math-bomb `won` ใช้ `eq.match(...)` โดยไม่เช็ค null — สมการที่ไม่ใช่รูป `NN op NN`
  (en dash, 3 พจน์, มีวงเล็บ) จะ throw ตอนนี้ blast radius ถูกจำกัดด้วย try/catch แล้วแต่ walk ยังพัง
- `page.locator("button", { hasText: "ตั้งค่า" })` เป็น substring match — ถ้ามีปุ่มที่สองที่มีคำนี้
  จะ throw strict-mode (math-bomb มี `ตั้งค่าภารกิจ` กับ `ตั้งค่าใหม่` อยู่แล้ว)
- `[class*="__mission"]` ก็ match `__missionMeta` ด้วย — วันไหนมี `strong` ในนั้นจะ throw

### เกมที่ยังไม่ได้ตรวจบางหน้าจอ

- `typing-defense` ยังมีหน้า `levelIntro` ที่เข้าได้เฉพาะโหมด adventure หลังเล่นจบรอบหนึ่ง — ยังไม่อยู่ใน config
- กลุ่ม C: `classroom-objects` กับ `vocabulary-arcade` **ปิดแล้ว** (ดูข้อ 3.5) เหลือ `typing-defense`
  หน้าเล่นจริง/หน้าจบ, `family-tree` stage 5, `phonics-bingo` — สามตัวนี้แพงกว่ากันหลายเท่า
- `sound-wheel`/`law-daily` ไม่มีหน้าผลลัพธ์โดยธรรมชาติของเกม (กลุ่ม D เดิม) — ไม่ต้องทำอะไรเพิ่ม

### phonics-bingo — ไอเดียที่ยังไม่ได้ลอง

เคยตัดออกเพราะคิดว่าทำอัตโนมัติไม่ได้ (ต้องฟังเสียงแล้วแตะให้ตรง) **แต่ยังไม่ได้ลองจริง**
เกมมีปุ่ม `👀 ครูดูเฉลย` ที่บอกว่าช่องไหนถูก — แนวทาง: กดดูเฉลย อ่าน DOM ว่าช่องไหนถูกทำเครื่องหมาย
แตะช่องนั้น กด `🔊 ฟังอีกครั้ง` ทำซ้ำจนบิงโกครบแถว ยังไม่ได้ลองว่าใช้ได้จริงหรือไม่

## 9. ลำดับที่แนะนำสำหรับรอบหน้า

1. **check "ปุ่มถูกทับ" แบบ scroll-aware** (ข้อ 3) — ช่องว่างที่เพิ่งทำให้เกมเล่นไม่ได้ทั้งเกมหลุดไปได้
   **แต่อย่าเขียนแบบ `elementFromPoint` ตรงๆ — ลองแล้ว ได้ false positive ล้วน** เหตุผลอยู่ในข้อ 3
   ต้องแยกเป็น pass ที่เลื่อน control เข้าจอก่อนแล้วค่อย hit-test (ประมาณสิ่งที่ Playwright ทำตอน click)
   ถ้าไม่คุ้ม ทางเลือกที่ถูกกว่า: ให้ทุกเกมมี walk แล้วพึ่ง `clickFirst` ที่ไม่ force ซึ่งจับได้อยู่แล้ว
2. **coding-maze `contentAboveStage` 76 แถว** — สัดส่วนสูงสุดของที่เหลือ
3. gate `contentAboveStage` ด้วย `controlsInside > 0` หรือรอ animation นิ่ง (ข้อ 4) ไม่งั้น check นี้จะถูกมองข้าม
4. accent ของจอสรุป science-lab (ข้อ 6) — บั๊ก `undefined` แก้แล้ว เหลือแค่ว่าจะให้จอนี้
   มี accent ของตัวเองไหม เป็นคำถาม design ล้วนๆ ไม่ใช่งานค้าง
5. `belowComfortTargets` 2675 แถว — ไม่เคยวิเคราะห์เลยว่าเป็นรูปแบบซ้ำๆ กี่แบบ (น่าจะเป็นปุ่ม toolbar
   34-42px ซ้ำกันหลายเกม เหมือนที่เจอตอนแก้ motion-lab) หรือกระจายจริง
6. ลอง phonics-bingo ผ่านปุ่มดูเฉลย ตามไอเดียข้อ 8
7. accessibility 2 จุดเดิม (digital-sort drag, sound-wheel canvas)
8. ลองวัดบนเครื่องจริงสักรอบสำหรับเคสที่ margin เหลือ 1-2px

**เฟสนี้ประกาศจบได้แล้วตามเกณฑ์เดิม** — ข้อ 1-8 ข้างบนเป็นงานคุณภาพเพิ่มเติม ไม่ใช่เงื่อนไขที่ค้างอยู่
