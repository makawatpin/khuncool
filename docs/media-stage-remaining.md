### ข้อ 3 คือบั๊กที่รุนแรงที่สุดของทั้งเฟส และเกือบหลุดไป

## 6. บั๊กเล็กที่รู้แล้วแต่ยังไม่แก้

### `styles.final` ของ science-lab-crisis ไม่มีอยู่จริง

`ScienceLabGame.tsx` เขียน ``className={`${styles.result} ${styles.final}`}`` แต่ CSS module
ไม่มีคลาส `.final` (มีแต่ `.finalButtons`) การ์ดสรุปจึงออกไปเป็น

และ styling ที่ตั้งใจให้จอสรุป "ผ่านครบ 10 ด่าน" ไม่เคยถูกใช้

โผล่มาเพราะ `expect` ตัวแรกที่ผมเขียนเล็ง `__final` แล้วหาไม่เจอ — ตอนนี้ selector เล็ง `__result` แทน
**ยังไม่แก้ตัวเกม** เพราะต้องรู้ก่อนว่า design ตั้งใจให้จอนี้ต่างจาก `.success`/`.fail` ยังไง

## 8. ข้อจำกัดที่ยังอยู่ (รู้ตัว ไม่ใช่ลืม)

### วัดจาก headless viewport ตายตัว

`dvh` บนมือถือจริงขยับตามแถบ URL ที่ซ่อน/โผล่ เวทีจริงจึงอาจสูงกว่าที่วัดได้เล็กน้อย
เคสที่คับที่สุดตอนนี้คือ family-tree `plant-tree` (เป้าแตะ 26px) กับ matching (25px)
ทั้งคู่เหลือ margin เหนือเกณฑ์ 24px แค่ 1–2px — **ควรลองบนเครื่องจริงสักรอบ** (ยังไม่ได้ลอง)

### harness ยังพึ่ง sleep คงที่

ทุกจังหวะรอใช้ `waitForTimeout` ค่าคงที่ ไม่ได้รอเงื่อนไขจริง — warmup ของ sound-wheel อย่างเดียว
นอน 5400ms × 12 = 65 วิต่อขนาด และเคยวัดพลาดมาแล้วครั้งหนึ่ง (วัดตอน explode keyframe ยังไม่จบ
ทำให้การ์ดพองไป 45% ต้องขยับเป็น 2500ms) เปลี่ยนไปรอเงื่อนไข (`toBeVisible`) จะเร็วกว่าและ
ตัดบั๊กประเภทนี้ทิ้งทั้งกลุ่ม แทนที่จะไล่จูนค่าคงที่ทีละครั้งที่โดน

### จุดเปราะใน harness ที่รายงานไว้แต่ยังไม่แก้

- solver ของ math-bomb `won` ใช้ `eq.match(...)` โดยไม่เช็ค null — สมการที่ไม่ใช่รูป `NN op NN`
  (en dash, 3 พจน์, มีวงเล็บ) จะ throw ตอนนี้ blast radius ถูกจำกัดด้วย try/catch แล้วแต่ walk ยังพัง
- `page.locator("button", { hasText: "ตั้งค่า" })` เป็น substring match — ถ้ามีปุ่มที่สองที่มีคำนี้
  จะ throw strict-mode (math-bomb มี `ตั้งค่าภารกิจ` กับ `ตั้งค่าใหม่` อยู่แล้ว)
- `[class*="__mission"]` ก็ match `__missionMeta` ด้วย — วันไหนมี `strong` ในนั้นจะ throw

### เกมที่ยังไม่ได้ตรวจบางหน้าจอ

- `typing-defense` ยังมีหน้า `levelIntro` ที่เข้าได้เฉพาะโหมด adventure หลังเล่นจบรอบหนึ่ง — ยังไม่อยู่ใน config
- กลุ่ม C เดิม (`classroom-objects`, `vocabulary-arcade`, `typing-defense` หน้าเล่นจริง, `family-tree` stage 5)
  ยังไม่ได้ประเมิน/เพิ่ม coverage — ต้องเล่นจริง ยากกว่ากลุ่ม A/B
- `sound-wheel`/`law-daily` ไม่มีหน้าผลลัพธ์โดยธรรมชาติของเกม (กลุ่ม D เดิม) — ไม่ต้องทำอะไรเพิ่ม

### phonics-bingo — ไอเดียที่ยังไม่ได้ลอง

เคยตัดออกเพราะคิดว่าทำอัตโนมัติไม่ได้ (ต้องฟังเสียงแล้วแตะให้ตรง) **แต่ยังไม่ได้ลองจริง**
เกมมีปุ่ม `👀 ครูดูเฉลย` ที่บอกว่าช่องไหนถูก — แนวทาง: กดดูเฉลย อ่าน DOM ว่าช่องไหนถูกทำเครื่องหมาย
แตะช่องนั้น กด `🔊 ฟังอีกครั้ง` ทำซ้ำจนบิงโกครบแถว ยังไม่ได้ลองว่าใช้ได้จริงหรือไม่
